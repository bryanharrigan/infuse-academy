Under the hood Open these to show how Absorb and this portal actually talk

1 — Certification check

Request / response ▸
What this proves
Picking a work order makes this portal ask Absorb one question: is
this installer certified for that panel series? The answer is what
locks or clears the billing hold above. Nothing on the page is
hard-coded — the verdict is fetched from the LMS every time, which is
exactly the call your CRM would make before letting a job be closed.
1 • The portal asks, on the installer's behalf
—
2 • Absorb answers

2 — Webhook delivery

Push, not polling ▸
What this proves
The check above is a pull. This is the push. The moment Absorb awards
a certificate it posts to this portal, signed, so clearance updates
without anyone refreshing anything. That is the difference between
"the hold clears overnight" and "the hold clears while the installer
is still on the roof".

3 — Live API call log

Every request ▸
What this proves
Every call this page makes, as it happens. Note what is not here:
the browser only ever talks to this portal's own origin. The Absorb
API key and the learner's token live on the server and are never sent
to the installer's device — which is the answer to "is this safe to put
in front of contractors?".

4 — Content delivery handshake

Embedded player ▸
What this proves
Open any course on this page and this fills in. The portal asks its
own server for a player URL; the server authenticates to Absorb; Absorb
mints a single-use URL, which is dropped into an iframe. The learner
never sees an Absorb-branded screen and never holds a credential. The
token is masked below because it genuinely never reaches this page.
